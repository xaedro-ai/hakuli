# Hakuli Design Notes

This document describes the algorithm implemented by `hakuli.optim.Hakuli`,
its memory model, and how it relates to prior academic work.

Hakuli is an independent, clean-room implementation written from published
algorithmic descriptions. See the repository `NOTICE` file for attributions.

## 1. Motivation

Full-parameter fine-tuning of modern language models is dominated by optimizer
memory: AdamW keeps two fp32 moments per trainable parameter, which is roughly
8 bytes per parameter, about 61 GB for a 7.6B-parameter model. Low-rank
optimizers reduce this by tracking moments in a compressed subspace, but
SVD-based projection methods (GaLore) pay a heavy periodic decomposition cost
and become unstable at small batch sizes, which are exactly the regimes where
single-GPU training operates.

Hakuli keeps the memory benefit while removing the SVD entirely: the subspace
is generated by a Gaussian random projection, which is cheap to draw and
cheap to resample.

## 2. Update rule

For a 2-D parameter with gradient `G_t ∈ R^{m×n}` and `m ≥ n`, Hakuli computes

```
R_t = P_t^T G_t                    (projected gradient, P_t ∈ R^{m×r})
M_t = β1·M_{t-1} + (1-β1)·R_t     (first moment, shape r×n)
V_t = β2·V_{t-1} + (1-β2)·R_t²    (second moment, shape r×n)
S_t = M_t / (sqrt(V_t) + ε)       (Adam-normalized direction)
s_t = ||S_t||_dim / ||R_t||_dim   (channel-wise scale, dim = 0 here)
U_t = sqrt(λ) · s_t ⊙ G_t          (full-rank structured update)
```

`P_t` is drawn from a standard Gaussian once, and resampled every
`update_proj_gap` steps. When `m < n` the projection is applied on the right
(`R_t = G_t P_t`, `P_t ∈ R^{n×r}`) and channel norms are taken along rows.
With `scale_type="tensor"` the vector `s_t` is replaced by the single scalar
`||S_t||_F / ||R_t||_F`.

The parameter update uses the scale-corrected step size

```
η_t = lr · sqrt(1 - β2^t) / (1 - β1^t)
W_t = W_{t-1} - η_t · U_t
```

which is the step-size correction used by APOLLO-style optimizers to match
AdamW's effective learning rate at the start of training.

Parameters that are not 2-D, or whose smallest dimension does not exceed
`rank`, are updated with the bias-free Adam-style direction `S_t` directly
(the same `η_t` applies). This keeps biases, normalization weights and small
tensors on a conventional update path.

## 3. Why random projections work

The channel-wise scale `s_t` only needs to approximate the geometry of the
Adam-normalized direction, not the direction itself; the update always
multiplies the *full* gradient `G_t`. By Johnson–Lindenstrauss-type arguments,
a Gaussian random projection preserves the norms of interest up to small
distortion once the rank is in the low hundreds. Because both the numerator
(`||S_t||`) and denominator (`||R_t||`) are computed in the same projected
space, first-order projection distortion largely cancels in the ratio.

Resampling `P_t` periodically avoids overfitting the scale estimate to a
single random basis. The moments `M_t`, `V_t` are carried across resamples;
their basis mismatch decays exponentially with the moment half-lives.

## 4. Norm-growth limiter

Low-rank scaling methods are prone to loss spikes when the estimated scale
jumps between steps. Hakuli applies a relative limiter: if the current update
norm exceeds `nl_threshold` times the previous step's update norm, the update
is rescaled so the growth factor is exactly `nl_threshold`:

```
limiter = max(||U_t|| / ||U_{t-1}||, nl_threshold) / nl_threshold
U_t ← U_t / limiter
```

With the default `nl_threshold = 1.01`, abrupt spikes become smooth
exponential growth. The limiter state is part of the optimizer state and is
restored by `load_state_dict`. A zero previous norm (e.g., a zero-gradient
first step) restarts the baseline instead of freezing the parameter.

## 5. Memory model

Per projected parameter of shape `m×n` (`r = rank`):

| Buffer | Shape | dtype | Bytes |
|---|---|---|---|
| Projection `P` | `r × max(m,n)` | bfloat16 | `2·r·max(m,n)` |
| First moment `M` | `r × min(m,n)` | float32 | `4·r·min(m,n)` |
| Second moment `V` | `r × min(m,n)` | float32 | `4·r·min(m,n)` |

Total: `2·r·max(m,n) + 8·r·min(m,n)` bytes versus `8·m·n` for AdamW.

Worked example: Qwen2.5-7B, `r = 256`:

| Component | Per unit | Count | Total |
|---|---|---|---|
| Embedding (151,936 × 3,584) | ~85 MB | 1 | ~85 MB |
| LM head (if untied) | ~85 MB | 1 | ~85 MB |
| Attention q/k/v/o (3,584 × 3,584 / 512) | ~24 MB | 28 | ~0.7 GB |
| MLP gate/up/down (18,944 × 3,584) | ~51 MB | 28 | ~1.4 GB |

Total optimizer state: **≈ 2.4 GB** versus ≈ 61 GB for AdamW fp32 moments.

## 6. Differences from prior work

| | GaLore (ICML'24) | APOLLO (MLSys'25) | Hakuli |
|---|---|---|---|
| Projection | SVD of gradient, periodic | random, fixed | random, resampled every `gap` |
| SVD cost | `O(mn·min(m,n))` per rebuild | none | none |
| Moments | projected | projected (scaled) | projected |
| Update | projected ascent + projection back | full-gradient, channel-scaled | full-gradient, channel-scaled |
| Small-batch stability | degrades (subspace noise) | stable | stable |
| Norm-growth limiter | — | — | yes (Fira-inspired) |

Hakuli's design follows the random-projection line of APOLLO, with the
addition of periodic resampling and the norm-growth limiter. No source code
from any of these projects is used.

## 7. Hyperparameter guidance

- `rank`: 128–512 covers most cases. `rank = 256` is a good default for
  1B–7B models. Lower ranks further reduce memory with mild quality impact.
- `scale`: compensates for the variance of the channel estimate. A useful
  heuristic is `scale ≈ hidden_size / rank`; 7B fine-tuning typically lands
  near 8–32. Tune with `rank` fixed.
- `update_proj_gap`: 100–500 steps. Smaller gaps refresh the basis more often
  at negligible cost.
- `lr`: same range you would use with AdamW for the same model (1e-6–1e-5 for
  7B fine-tuning). The `η_t` correction matches AdamW early-step magnitude.
- `nl_threshold`: `1.01` by default. Increase (e.g., 1.05) to allow faster
  norm growth when the loss is known to be stable.

## 8. Limitations

- The optimizer targets fine-tuning-scale training; from-scratch pre-training
  at very long horizons may prefer full-rank AdamW if memory allows.
- The projection is stored in bfloat16; extremely small gradient scales may
  benefit from `scale_type="tensor"` or a larger `rank`.
- Sparse gradients are not supported.
- `state_dict()` follows the standard PyTorch convention of casting floating
  point state to the parameter dtype, so a bfloat16 projection round-trips
  through a float32 parameter dtype. Values are preserved exactly.
